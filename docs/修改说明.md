# 对 `docs/说明.md` 里四条问题的处理（含第二、三轮）

对应关系逐条写明：现象 → 根因 → 改了什么 → 怎么验。

> **第二轮**（短标签 + 统一界面）与**第三轮**（桌面版「需要票据」+ 误报的降级提示）见文末。
> 第二轮是跟着你的补充做的："WebUI 和应用 UI 基本一致，在桌面版里用同一套界面和体验管理远程
> （WSL / 虚拟机 / 远程链接）"。

## 2、镜像区一直在抖，什么都显示不出来

**根因有两个，都是实测出来的，不是猜的：**

1. **`<webview>` 被无限重载。** `<webview>` 的 `dom-ready` 事件对**每一次**导航都会触发，而代码是
   "每次 dom-ready 都 `setAttribute('src', entryUrl)`"——于是：加载 → dom-ready → 再设一次 src →
   再加载 → ……每几百毫秒一轮。界面当然一直在抖，也永远渲染不出东西。
   现在导航只做一次（`navigated` 闸门），并且导航后另有 10 秒超时兜底。
2. **载体被反复重建。** 载体 effect 的依赖里放着宿主服务对象，而那个对象**每次渲染都是新的**
   （slot 的 `inject` 回调每次调用都返回新对象）。外壳一重渲染，effect 就"拆掉视图 → 重新挂一个"，
   表现同样是闪。现在服务走 `useRef`，依赖只剩「镜像地址」「容器偏好」——只在这两件事变了才重建。

**另外**：桌面原生视图"挂上了却是空的"以前只给一个「改用内嵌框架」按钮，现在会**自动降级**——
加载完成后等 2.5 秒探一眼 guest 里到底有没有内容，确实是空的就换成内嵌框架，并在下方写明原因。

**怎么验**：`pnpm smoke` 里有两条回归断言（`navigated` 闸门、自动降级路径）。
真机上打开面板看镜像区是否稳定即可。

## 3、本机内置运行应该默认是「启动的」，却显示「未启动」

**根因**：桌面应用打开时，本机那套 DSH（`app.asar` 里的内置运行时）**本来就在跑**——你现在看的
这个界面就是它。而插件把 `kind: local` 当成"再拉一份同样的运行时"，所以它显示的是"未启动"。

**改了什么**：新增**吸附**（attach）。`kind: local` 的实例默认接上宿主自己：

- 不新起进程、不建 profile：镜像直接指向宿主自己的 `127.0.0.1:<宿主端口>`（端口从
  `webServer.port` 拿，桌面版是 19387）；
- 会话 cookie 用宿主自己的进程令牌换（`connection.authenticatedUrl()`，桌面壳启动时走的同一条路）；
- **打开应用就已经是「运行中」**（`autoAttach`，插件装载时自己接上，不用点任何按钮）；
- 「停止」只收掉镜像端点，**不会**把桌面应用关掉，随后随时可以再吸附；
- 「更新」对它明确拒绝（它的版本跟着桌面应用走），而不是假装升级成功。

**判定规则**（`attach` 留空即自动）：

| 配置 | 行为 |
|---|---|
| 留空 | **桌面版内置运行时**才吸附。`dsh web`、验证脚本起的临时宿主等非桌面宿主照旧自己拉进程——老配置语义不会被悄悄改掉 |
| `attach: true` | 无论宿主是什么都吸附 |
| `attach: false` | 永不吸附，照旧用独立 profile 拉一份自己的 DSH |

**踩到的两个启动时序**（已在实现里等住/重试，否则第一次吸附会失败）：

1. `connection` 服务可能比本插件的 `apply` 晚挂上 → 那时拿不到进程令牌，裸地址换不到 cookie。
   现在会**等令牌到位**（最多 20 秒）再换。
2. 前端静态兜底（`/` 那条路由）在启动期还没注册 → 那时任何未匹配请求都会拿到 **404**。
   现在的会话换取会**退避重试**（最多 8 次），并且每轮重新探一次令牌。

**怎么验**：`pnpm smoke` 里第 [9] 节用假宿主把这条路走了两遍（含"早期 404"和"令牌迟到"两种情形，
并断言过程中**没有**调用 subprocess）；`pnpm verify:live` 在真实 DSH 宿主上跑通
自动运行中 → 镜像往返 → 停止不动宿主 → 再吸附。

## 4、在窗口角上加一个「本机 / WSL」下拉框

**做了什么**：注册进官方的 `shell.overlay`（帧级浮层，**增量座位**——新 id 加在既有条目旁边，
不顶掉官方的；`shell.leading` 那种 `single` 座位会顶掉别人，而且只在侧栏完全收起时才挂载）。
默认贴右上角，位置可配：

```yaml
switcher:
  enabled: true
  corner: top-right     # top-right | top-left
  offsetX: 56           # 距边缘的像素
  # offsetY 留空 = 跟随官方 --dsh-frame-overlay-top（桌面版 = 标题栏高度 + 20px）
```

**两处摆位不是拍脑袋的**：

- 纵向基线用官方 token `--dsh-frame-overlay-top`（`dsh-client-ui-layout` 里就是给帧级浮层算的：
  桌面版 = 标题栏高度 + 20px，全屏 20px），所以窗口按钮、标题栏拖动区都不会被它压住；
- 默认 `offsetX: 56` 躲开主区右上角那颗官方侧栏开关；**本面板的表头会让出切换器的实测宽度**
  （切换器把自己的宽度写进 `--drd-switch-reserve`）——第一版没做这件事，截图里
  「复制诊断 / 刷新」就被它压住了，真实浏览器验证一跑就露出来了，这也是为什么这一条现在有断言。

**选中一项做什么**：① 记下选中 → ② 需要的话把它跑起来（本机那一项是吸附，不拉新进程）
→ ③ 把主区切到「远端工作台」面板。所以"选本机就连本机的服务端口、选 WSL 就连 WSL 的服务端口"
是一次点击的事。下拉框旁边的状态点跟着当前那台走，起不来时**在那里直接写明原因**。

**面板与它共用同一份状态**：新增客户端共享 store（`src/client/workbench.ts`）——一个轮询、一个
选中项，两处 UI 都从这里读，不会出现"切换器选了 WSL、面板还停在本机"。

**怎么验**：`pnpm smoke` 里把切换器渲染了三遍（正常 / `enabled: false` / 没有实例），
断言下拉项、选中项、状态点、贴角与 CSS 变量；`pnpm verify:ui` 在真实 Chromium 里断言它在窗口角上、
在视口内、接回了指针事件、列出实例、与面板选中项一致、并且让出了自己的宽度（23 项全过）。

客户端那一半是**应用启动时读进内存**的（官方 bundle 地址带内容哈希），所以**必须完整重启桌面应用**
才看得到新面板与新切换器——刷新窗口不够。重启后：

1. 窗口右上角是一个很短的下拉框：`本机` / `WSL · Ubuntu-24.04`，旁边两三个字的状态；
2. 「远端工作台」默认就是**统一界面**：`local-dev` 那台机器的 DSH 界面铺满整个主区

若某一步不对，点「管理」→「复制诊断」把那段文本贴回来即可——里面会写明

## 第二轮：短标签 + 统一界面

### 1、下拉菜单字太多

下拉项现在只留**关键字**：

| 原来的样子 | 现在 |
|---|---|
| `本机（内置运行时）（运行中）` + 旁边一长串「运行中（吸附宿主自身，端口 19387）」 | `本机` + 旁边两个字：`运行中` / `已连接` / `未启动` / `出错` |

规则：去掉 label 里的括注（`本机（内置运行时）` → `本机`），label 里没有类型词就补一个
（`虚拟机 Ubuntu` → `SSH · 虚拟机 Ubuntu`），类型词已经有了就不重复。完整说明（端口、吸附、
错误原因）全部进 `title`，鼠标一悬停就有——**信息没丢，只是不占地方**。

### 2、统一界面：和 WebUI 一样的界面和体验，只是换了台机器

原话是"我原本的想法是 webui 和应用 UI 基本一致，我想利用一样的 UI 和体验，在桌面版本实现对远程
界面统一管理，包括（wsl / 虚拟机 / 远程链接）"。所以面板现在有**两种形态**：

| 形态 | 长什么样 | 什么时候用 |
|---|---|---|
| **统一界面**（默认） | 选中那台机器的 DSH 界面**铺满整个主区**，我们自己的列表 / 工具栏 / 日志全部收起，只剩右下角一条半透明浮条（关键字 + 状态 + 全窗口 / 重载 / 管理） | 平时干活：本机、WSL、虚拟机、远程链接，点一下就是那台机器的那套界面 |
| **管理界面** | 实例列表 + 工具栏（预检 / 启停 / 更新 / 回滚）+ 镜像 + 日志抽屉 | 配置、排障、更新版本 |

- 形态按钮就在明面上（浮条上的「管理」、表头上的「统一界面」），选择**记在本地**，
  下次打开还是你上次那个；
- 默认形态由配置 `layout.mode` 决定（`immersive` / `manage`），用户点过之后以用户为准；
- **「全窗口」**：一键把官方侧栏收成窄条，远程那套 UI 就拿到整扇窗——这是"基本一致"的最后一块拼图
  （官方侧栏是应用自己的导航，收起来之后屏幕上就是我们和 WebUI 一模一样的那套界面）；
- **「重载」**：重新挂载镜像载体，卡住或想重走一遍票据时最省事；
- 实例没起来时不是把人丢回管理界面，而是一张能直接点「启动」的小卡片。

虚拟机怎么接：虚拟机走的就是 `ssh`（有 sshd）或 `wsl`（WSL2 里的发行版），所以**不用新的 kind**——
给它起个短 `label`（例如 `虚拟机 Ubuntu`），下拉框里就是那个关键字。

### 3、这一轮怎么验

| 命令 | 结果 |
|---|---|
| `pnpm smoke` | **258 项通过**：短标签（去括注 / 补类型词 / 退回 id）、状态词、形态判定（配置默认 / 用户覆盖）、统一界面渲染（无列表无工具栏、有镜像区、浮条三个按钮）、未运行的启动卡片、切回管理界面后列表工具栏都在 |

## 第三轮：桌面版里的「需要票据」与那句误报的降级提示

你在桌面版里看到两条：

```
需要票据
请从「远端工作台」面板打开这个实例——镜像端点只接受带票据的访问。

桌面原生视图没有导航到镜像地址（主进程可能拒绝了挂载）。已改用内嵌框架。
```

**两条都是真 bug，根因不同：**

### 1、「需要票据」——跨站 iframe 里 SameSite=Lax 的 cookie 不会被带上

镜像端点用一张一次性票据换 cookie 之后才放行。桌面版里顶层文档是 `dsh-app://app`
（**不是 http 源**），所以嵌进去的镜像是一个**第三方 iframe**；而 `SameSite=Lax` 的 cookie
在第三方 iframe 的请求里**根本不会被带上**——于是每一个子请求都撞回 403「需要票据」。

这也解释了为什么纯 Web 外壳（顶层就是 `http://127.0.0.1:…`，与镜像是同站）一切正常，
只有桌面版出问题：同站时 `Lax` 会带，跨站时不会。

**改了什么**：票据 cookie 按请求的 `Sec-Fetch-Site` 自适应——

- 跨站（`cross-site`，或拿不到这个头时按最保守处理）→ `SameSite=None; Secure`；
  `Secure` 在 `http://127.0.0.1` 上是被允许的（Chromium 把回环当可信来源）；
- 同站 → 仍旧 `SameSite=Lax`，少给一点权限。

**怎么验**：`pnpm verify:ui` 新增一条**跨站 iframe 回归**——用另一个窗口把顶层换成
`http://localhost:<port>`（与 127.0.0.1 不同站）和 `file:///…`（更接近桌面版那种非 http 顶层），
iframe 直指镜像入口，然后在主进程侧读取子帧内容：

```
ok  localhost：镜像帧存在 — http://127.0.0.1:19600/
ok  localhost：不再显示「需要票据」
ok  localhost：渲染出远端 UI
ok  跨站 iframe 下发的票据 cookie 是 SameSite=None; Secure — dsh_mirror=…; Path=/; HttpOnly; SameSite=None; Secure
ok  file：镜像帧存在 / 不再显示「需要票据」/ 渲染出远端 UI
```

冒烟测试里也补了纯函数与端到端：跨站访客拿到的是 `SameSite=None; Secure`、同站访客拿到的是
`Lax`、带上跨站 cookie 能取回上游内容、不带仍旧 403。

### 2、那句"没有导航到镜像地址"是**误报**

`<webview>` 的 `did-finish-load` 对最初那一跳 `about:blank#<lease>` 也会触发。上一版把
"加载完成后看一眼 URL，还是 about:blank 就算没导航"写在了这个回调里——于是在**导航还没开始**
的时候就读到了 about:blank，立刻降级并给出那条听起来很严重的提示（其实主进程什么都没拒绝）。

**改了什么**：

- 降级判定只在**真的发出过导航之后**才生效（`navigated` 闸门），并且导航后 1 秒内到达的那次
  "加载结束"直接忽略（那一定是 about:blank 那一跳的尾巴）；
- 三个看门狗都缩短并写清了各自的原因：挂载 6 秒没就绪 / 导航后 8 秒没加载完 /
  加载完 2.5 秒后里面还是空的；
- "没导航"那条提示现在会把**当时的地址**一起打出来，下一次一眼就能分清是"主进程拒绝挂载"
  还是"导航慢"。

### 3、桌面版里你会看到什么

重启后按顺序是：先试桌面原生视图（官方 webview lease），它要是挂不上 / 没导航 / 渲染不出来，
就自动换成内嵌框架并写明原因；而内嵌框架这条路现在**能用了**（第 1 条修的就是它）。
想直接锁定内嵌框架，配置里写 `mirror.openMode: iframe` 即可。

> 说明一下分工：**跨站 cookie 那条是能在本机复现并验证的**（上面那两个跨站顶层就是复现手段）；
> 而"桌面原生视图到底能不能挂上"取决于桌面主进程的租约放行规则，那半边只有真桌面应用里才算数——
> 现在失败时至少会给出准确的地址与原因，而不是一句含糊的"可能被拒绝了"。

## 第四轮：渲染太慢 + 下拉框挡住图标

### 1、"能不能利用软件本身的界面只改接口"

**直说：这件事做不了，而且不是难度问题，是所有权问题。** 应用自己那套界面（本地 DSH 前端）
之所以是"应用自己的"，是因为它跟**本地宿主**绑死在三处：

| 绑在哪 | 谁拥有 | 想换一套后端要动什么 |
|---|---|---|
| `window.__DSH_BOOT__`（注入表 + `streamBaseUrl`） | 官方前端入口，启动时由本地宿主注入 | 得替换官方前端的引导数据与模块图 |
| 会话 / 工作区 / 设置的取数（`/api` 共享通道 + RPC over WS） | 官方 `dsh-client-connection` / `dsh-api-gateway` 等插件 | 得把这些插件的传输层整体改指向另一台机器，还要保证两边状态一致 |
| WS 的 `Origin` 放行 + 会话 cookie | **桌面主进程**（`dsh-app://app` 只放行主窗口，cookie 绑定 authority） | 这是 Electron 主进程里的守卫，插件根本改不到 |

也就是说：要么替换官方前端与传输层（每次 DSH 升级都会碎，而且会打破"你看到的界面 = 拥有你会话的宿主"
这条不变量），要么就**把另一台机器上那套一模一样的界面搬进来**——后者才是官方支持的形态
（远端跑的仍旧是它自己那一版前端）。这个插件从第一天做的就是后者。

**但"渲染太慢"是真问题，也确实能治。** 把它拆成四份成本，一份一份挪走：

| 成本 | 以前 | 现在 |
|---|---|---|
| 载体选择 | `auto` 先试桌面原生视图：申请租约、等主进程放行，失败还要等看门狗（最坏 6–8 秒）才降级 | **`auto` 直接走内嵌框架**，第一屏立刻开始加载；想要原生视图（独立分区、不共享 DOM）就显式写 `openMode: webview` |
| 镜像 origin 每次都换 | 端口按范围顺序分配 → 换端口就是换 origin → 浏览器缓存与镜像里那套 DSH 的 localStorage 全部作废 | **按实例复用上次的端口**（冒烟断言：再吸附复用同一端口、但票据是新的） |
| 同一份前端 bundle 反复回远端要 | 远端那套是按需组合的（`plugins/??a,b,c&rev=…` 第一次请求才现读现拼几 MB） | 镜像端点给**内容寻址**的资源做内存缓存（32 MB 预算，只认 `rev=` / `-<hash>.js`；`/api/*`、无哈希、带 `content-encoding` 的都不进；响应头 `x-drd-cache` 可查） |
| 切回来要重新渲染 | 切走就卸载 iframe，切回来重新下载 + 挂载 + 连 WS | 最近看过的 **3 台保持挂载**（隐藏但不卸载），切回来连 WS 都没断——真正的瞬间切换 |

外加一条：**实例一就绪就预热**——后台把首页引用的前端资源先抓一遍（并发 3、60 秒预算、尽力而为），
远端的"现拼"成本在用户切过去之前就付掉了；日志里写 `预热：N/M 个前端资源已进镜像缓存`。

> 预热这条在活体验证里翻过一次车，值得记下来：预热用的是 Node 的 `fetch`，它会**自动解压**；
> 而浏览器请求带的是 `accept-encoding: gzip`。两种字节混进同一个缓存 key，就会把"解压后的字节 +
> gzip 头"发给浏览器，脚本直接报"资源没加载完"。现在的规矩是：**带 `content-encoding` 的响应一律不进缓存**，
> 预热也显式带 `accept-encoding: identity`。活体验证里现在能读到：第一次取子资源就已经命中缓存
> （`cache=hit`，长度 33750），第二次仍旧命中且字节一致。

### 2、下拉框挡住图标 → 挪到上边中间（第五轮又改成"钻进标题栏"）

默认 `top-center`）：右上角那颗官方侧栏开关和面板自己的按钮都不再被压住。

**但你截图里的问题是另一回事**：居中之后它落在了 `--dsh-frame-overlay-top`（标题栏高度 + 20px），

而且它挂上去就不再动，窗口一改尺寸它也不会跟着挪。

**第五轮的改法**：位置改成**自己算**，优先钻进**窗口标题栏那一条**——

### 顺带说明：两处"假失败"

调试期间踩到过两次看起来像 bug、其实不是的现象，写下来免得下次又查一遍：

1. **第一次 `verify:live` 的吸附失败是真空。** 日志里写「吸附目标：`http://127.0.0.1:19412/`」——
   没有 `?token=`。原因是那个地址探得太早：`connection` 服务还没挂上，只能拿到裸地址；
   而裸地址在启动早期还会撞上"前端兜底路由尚未认领 `/` → 一律 404"。
   现在会等令牌（≤20 秒）+ 退避重试（≤8 次），两处都补了冒烟断言。
2. **`verify:ui` 报 `[exit code: 1]` 是 PowerShell 的。** 脚本自己的退出码是 0
   （`LASTEXITCODE=0`，`results.json` 里 21/21 通过、`consoleErrors` 为空）——
   Electron 那句 `'console-message' arguments are deprecated` 写在 stderr 上，
   被 PowerShell 当成错误记录渲染了。
